# Architecture

Current, built architecture. Planned components live in `docs/technical-discovery.md` and `docs/adr/`.

## Monorepo (ADR 0003)

pnpm workspace (`pnpm-workspace.yaml`), pnpm pinned through `packageManager` in the root `package.json`.

- `apps/api` (`@bricomission/api`): NestJS 12 REST API, ESM (`"type": "module"`, `module: nodenext`, relative imports end in `.js`). Prisma 7 with the `@prisma/adapter-pg` driver adapter.
- `packages/shared-types` (`@bricomission/shared-types`): type-only contracts (`HealthResponse`, `RealmRole`, `MeResponse`, `AdminPingResponse`, `GpuJobView`, `GpuJobEvent`, ...). No runtime code and no build step. Consumers use `import type`; the API lists it as a devDependency.
- `apps/web` (`@bricomission/web`): Next.js 16 App Router PWA (React 19, Tailwind CSS 4, `next-intl` 4). See "apps/web layout" below.
- `packages/api-client` (`@bricomission/api-client`): typed API client. `openapi.json` is a committed snapshot of the API's `/docs-json`; `src/schema.ts` is committed `openapi-typescript` output; `src/index.ts` exports `createApiClient(baseUrl, fetch?)` (`openapi-fetch`). Source-only (no build step); `apps/web` consumes it through `transpilePackages`.

Root configs: `tsconfig.base.json` (strict), `eslint.config.mjs` (flat config, typescript-eslint recommended, `consistent-type-imports`; ignores `.next`, `next-env.d.ts`, test output and the generated `schema.ts`). Every package exposes `lint` (ESLint + `tsc --noEmit`) and `test`.

### OpenAPI client regeneration loop

1. Change an API route or DTO.
2. `pnpm --filter @bricomission/api openapi:export`: `apps/api/test/openapi-snapshot.spec.ts` builds the app like the HTTP tests (`PrismaService` stubbed, default env, no debug routes), runs `createOpenApiDocument` (`src/app.setup.ts`, the same document `/docs-json` serves) and, with `UPDATE_OPENAPI_SNAPSHOT=1`, writes `packages/api-client/openapi.json`. It then runs `pnpm --filter @bricomission/api-client generate` (`scripts/generate.ts`, programmatic `openapi-typescript`) to rewrite `src/schema.ts`.
3. Commit both files. Drift fails `pnpm -r test` twice: the api snapshot test deep-equals the committed JSON, and `packages/api-client/test/schema.spec.ts` fails when `schema.ts` is stale.

- `src/app/layout.tsx`: root layout; `<html lang>` from the resolved locale, `viewport` (`themeColor` `#1F4E79`, `viewport-fit=cover`), metadata (apple-touch icon), `NextIntlClientProvider`, service worker registration (production builds only).
- `src/app/page.tsx`: Home (dynamic). Wordmark, header actions (`LanguageSelector`, `AccountEntry`), hero, 3 steps, the professional link (`/professionals/register`), sticky bottom bar with `ApiStatus` and the primary CTA (`/kitchen-projects/new`). Header fixed, content scrolls in `main`, bottom bar fixed, all inside an `h-dvh` column.

Form field `locale` must be in `LOCALES` (else 400); a present `Origin` must match `Host` (else 403). Success: `Set-Cookie: NEXT_LOCALE=<l>; Path=/; Max-Age=31536000; SameSite=Lax` and 303 to `/`.
- `src/app/api/[...path]/route.ts` (`src/lib/api-proxy.ts`): same-origin proxy to the API, see below.
- `src/app/auth/{login,callback,logout,session}/route.ts` and `src/app/auth/error/page.tsx`: web sign-in (BFF), see "Web sign-in" below.
- `src/app/manifest.ts`: `/manifest.webmanifest` (`standalone`, `start_url`/`scope` `/`, theme `#1F4E79`, background `#FAFAF8`, icons 192, 512, 512 maskable).
- `src/proxy.ts` (Next 16 proxy, formerly middleware): locale resolution for page routes, see i18n.
- `src/components/`: `LanguageSelector` (pill + modal `<dialog>` bottom sheet; options are buttons with `aria-current` on the current language, then `POST /locale` and `router.refresh()`; below 375 px a compact pill that keeps the full native name at 12/16), `AccountEntry` (client; "Sign in" link or the account button plus the account `<dialog>` sheet with the sign-out form; hydrates from `GET /auth/session`), `ApiStatus` (client; `data-state` `checking|online|degraded|offline`, `aria-live="polite"`, dot plus label), `Wordmark`, `ServiceWorkerRegistration`.
- `src/app/globals.css`: Tailwind 4 `@theme` mirroring every DESIGN.md token (colors, Inter, type scale `display|h1|h2|body|small`, radii, `shadow-card|sheet`, spacing `xs..xxl`) and the self-hosted Inter `@font-face` (latin + latin-ext woff2 from `@fontsource-variable/inter`). Icons: `lucide-react` (inline SVG).
- `public/sw.js`: hand-written service worker, versioned cache. Install precaches the manifest and icons only; navigations are network-first (200 non-redirected responses cached, the cached copy served offline with `ignoreVary`); `/_next/static/*`, fonts and icons are cache-first; `/api/*`, `/auth/*` and non-GET requests are never intercepted (cache `v2`); activate deletes old caches and claims clients. `/sw.js` is served with `cache-control: no-cache`.
- `public/icons/`: PNGs scaled from the approved design export by `scripts/render-icons.ts` (run in the Playwright image; committed).
- `messages/<locale>.json`: one file per locale, namespaces `meta`, `home`, `language`, `status`, `auth`.

### i18n (11 locales, no locale in the URL)

- `src/i18n/locales.ts`: `LOCALES` (en, es, fr, de, it, pt, nl, sv, no, da, fi), `DEFAULT_LOCALE` `en`, `LOCALE_NATIVE_NAMES` (constants, never translated) and the pure `resolveLocale(cookie, acceptLanguage)`.
- Resolution order: a valid `NEXT_LOCALE` cookie, then the highest-q supported primary subtag of `Accept-Language` (ties keep header order; `nb`/`nn` map to `no` (Bokmål); `pt-BR`/`pt-PT` to `pt`; `*` and `q=0` are unsupported), else none.
- `src/proxy.ts`: `/` with no resolved locale redirects 307 to `/language`. Other pages get the resolved locale (fallback `en`; always `en` on `/language`) in the request header `x-bricomission-locale`, overwriting any client value. `src/i18n/request.ts` (next-intl "without i18n routing") reads it and loads the messages.
- Detection never writes the cookie; only an explicit choice does, so a later browser-language change is followed until the visitor chooses. Saving the language on the account is `language-preference-account`.
- Offline, the service worker serves Home in the locale it was cached in.

### Same-origin API proxy (no CORS)

The browser calls `/api/*` on the web origin; `src/lib/api-proxy.ts` forwards to `API_INTERNAL_URL` (runtime env; compose `http://api:3000`, dev default `http://127.0.0.1:3000`). A route handler, not `rewrites`, because standalone output bakes rewrites in at build time. Rules:

- Target = fixed base + re-encoded path segments + original query. Segments that decode to `.`/`..` or contain `/` or `\`, and bad percent-encoding, give 400 before any upstream call.
- Forwarded request headers: `accept`, `accept-language`, `content-type`, `last-event-id` only (never cookies, never the browser's `Authorization`); method and streamed body (`duplex: 'half'`).
- `Authorization: Bearer <access token>` comes from the server session only (`resolveAccessToken`, injected by the route; see "Web sign-in"). No session: upstream gets no `Authorization` (`/api/me` gives 401). Session lookup or refresh unavailable (database or Keycloak down while a `bm_session` cookie is present): 503 `{"status":"error"}`. `invalid_grant` or a stale cookie: forwarded anonymously plus a cookie-clearing `Set-Cookie`.
- CSRF: with a `bm_session` cookie, `POST`/`PUT`/`PATCH`/`DELETE` need an `Origin` whose host equals `Host`; a missing or foreign `Origin` gives 403 before any lookup or upstream call.
- Returned: upstream status, `content-type`, `cache-control` (default `no-store`), `www-authenticate`, streamed body.
- Upstream unreachable: 502 `{"status":"error"}`; the log line carries the error class name only.
- The future native iOS client calls the API directly.

### Web sign-in (BFF; homeowner-password-login)

The Next.js server is the OIDC client `bricomission-web` (confidential, Authorization Code + PKCE S256, `state`, `nonce`); the Keycloak pages are the themed realm pages. Tokens never reach browser JavaScript, HTML or the service worker.

- `src/lib/auth/`: `config.ts` (env), `oidc.ts` (`openid-client` 6.9.0 with explicit metadata, no discovery: `issuer` and `authorization_endpoint` on `KEYCLOAK_PUBLIC_URL`; `token_endpoint`, `jwks_uri`, `end_session_endpoint` on `KEYCLOAK_INTERNAL_URL`; ID token signature verified against the JWKS, plus `iss`, `aud`, `nonce`, `exp` and the authorization response `iss`), `session.ts` (cookies, `getSession`, `getValidAccessToken` with a per-process single-flight refresh 30 s before expiry), `handlers.ts` (route logic), `runtime.ts` (lazy process-wide wiring on `globalThis`), `return-to.ts` (`safeReturnTo`: single-`/` paths only), `origin.ts` (CSRF rule).
- Routes: `GET /auth/login?returnTo=&mode=register` (307 to `WEB_PUBLIC_URL` first when the `Host` differs, because cookies are host-scoped; stores a login transaction; 303 to Keycloak with `ui_locales` = the web locale; `mode=register` adds `prompt=create`). `GET /auth/callback` (transaction taken and deleted on first use; state, OAuth error, code exchange and ID token checks; 303 to `returnTo` with a new session, or to `/auth/error?reason=cancelled|expired|unavailable|failed[&returnTo=]`). `POST /auth/logout` (Origin checked; backchannel `POST .../logout` with client credentials and the refresh token, 3 s timeout; the row is deleted and the cookie cleared even if Keycloak is down; 303 to `/`). `GET /auth/session` (`no-store`; `{"signedIn":false}` without touching the database when there is no cookie, else `{"signedIn":true,"user":{"username","displayName"}}`; 503 when the database is down). `/auth/error` is the designed page.
- Cookies: `bm_session` (32 random bytes base64url, `HttpOnly; SameSite=Lax; Path=/`, `Secure` on https, Max-Age 10 h) and `bm_auth_tx` (same flags, Max-Age 600).
- Storage: schema `web_session` in the shared PostgreSQL database, owned by the web (`pg` 8.23.1; pool max 5, 2 s connect timeout). The API's Prisma owns `public` and neither app touches the other's tables. `src/lib/auth/db/migrations.ts` holds the SQL as string constants and applies missing versions lazily, once per process, in one transaction under `pg_advisory_xact_lock` (table `web_session.schema_migrations`; append-only). Tables: `sessions` (key `id_hash` = SHA-256 of the cookie; `sub`, `username`, `display_name`; `access_token_enc`/`refresh_token_enc` bytea and their expiries) and `auth_transactions` (`state`, `nonce`, `code_verifier_enc`, `return_to`, `locale`, `expires_at`; 10 min). The ID token is not stored.
- Encryption: AES-256-GCM with `WEB_SESSION_KEY` (base64, 32 bytes): version byte + 12-byte IV + 16-byte tag + ciphertext; AAD = a purpose label plus the row's `id_hash`. A row that fails to decrypt (key changed) is deleted and treated as absent. A bad or missing key or secret makes the sign-in routes answer "unavailable" (logged class name only).
- Cleanup: lookups ignore expired rows; inserts delete expired transactions and sessions at most once per 10 min per process; more than 5000 open transactions refuse new logins (`/auth/error?reason=unavailable`).
- Home HTML is the same for every visitor; `AccountEntry` hydrates from `/auth/session`.

`ApiStatus` calls `client.GET('/health')` through `@bricomission/api-client` with a 5 s `AbortSignal.timeout`, on mount and on the `online` event: 200 `database: up` is `online`, 503 `database: down` is `degraded`, anything else (network error, timeout, proxy 502) is `offline`.

## apps/api layout

- `src/main.ts`: creates the app, applies `configureApp`, listens on `0.0.0.0:$PORT` (default 3000).
- `src/app.setup.ts`: `configureApp(app)`, shared by `main.ts` and the HTTP tests. Shutdown hooks and OpenAPI: Swagger UI at `/docs`, JSON at `/docs-json`, assets served locally from `swagger-ui-dist` (works offline). No global route prefix.
- `src/app.module.ts`: root module importing feature modules.
- `src/prisma/`: global `PrismaModule` with `PrismaService` (extends the generated `PrismaClient`). It connects lazily on the first query, so the API boots and stays up while PostgreSQL is down; `$disconnect` runs on shutdown.
- `src/<feature>/`: one Nest module per feature (controller, service, Swagger DTO classes that `implement` shared types): `src/health/`, `src/catalog/`.
- `src/auth/`: Keycloak JWT authentication (`jose`). `AuthModule` registers two global guards with `APP_GUARD`, in this order:
  - `AuthGuard` is default-deny: every route needs `Authorization: Bearer <jwt>` unless the handler or controller is marked `@Public()`. `TokenVerifier` checks the RS256 signature through the `KEY_RESOLVER` provider (a lazy `createRemoteJWKSet` on `KEYCLOAK_JWKS_URL`, 3 s timeout, so the API boots without Keycloak), plus `iss` (`KEYCLOAK_ISSUER`), `aud` (`KEYCLOAK_AUDIENCE`) and `exp`. Missing or invalid tokens give 401 with `WWW-Authenticate: Bearer realm="BricoMission"`; a JWKS that is unreachable, times out or answers garbage gives 503. Bodies are the generic Nest error bodies and logs carry class names only.
  - `RolesGuard` enforces `@Roles(...roles: RealmRole[])`: 403 unless the caller holds one of the roles. Roles come from `realm_access.roles`, filtered to `user`, `professional`, `admin`.
  - `@CurrentUser()` injects the `AuthenticatedUser` (`sub`, `username`, `email`, `roles`). `GET /me` lives here.
- `src/admin/`: `AdminController` (`@Roles('admin')` on the class) with `GET /admin/ping`; later admin features extend this module.
- `src/ai/`: AI layer (`AiModule.register()`, a dynamic module). See "AI layer and GPU job broker" below.
  - The `AuthGuard` is global and default-deny, so the AI job routes (`/ai/jobs/*`) require a valid token; tests that build `AiModule` alone run without the guard.
- `prisma/schema.prisma` + `prisma.config.ts`: Prisma 7 keeps the datasource URL in `prisma.config.ts` (`DATABASE_URL`). The client is generated into `src/generated/prisma` (git-ignored); `lint`, `test` and `build` run `prisma generate` first.
- `prisma/migrations/`: SQL migrations applied with `prisma migrate deploy`. The api container's `docker-entrypoint.sh` runs it best-effort on start (bounded by a 60 s timeout). On failure it logs `migrations not applied` and starts the API anyway, so the API still boots with the database down. `scripts/catalog/ingest.sh` also runs it. `prisma` is a runtime dependency and the runtime image installs `openssl` for the schema engine. The first migration (`*_catalog_rag`) is generated by `prisma migrate diff` and then hand-edited (`CREATE EXTENSION vector`, HNSW index). Features that change the schema must keep hand-written SQL such as that HNSW index in their own migrations, because Prisma does not model it.

### Catalog module (`src/catalog/`, ADR 0002 and 0004)

- `embedding/embedder.ts`: the `Embedder` interface (`model`, `dimensions`, `embedDocuments`, `embedQuery`), `CATALOG_EMBEDDING_DIMENSIONS = 1024`, and the errors `EmbeddingUnavailableError` and `EmbeddingDimensionError`. `llama-server.embedder.ts` is the OpenAI-compatible `POST /v1/embeddings` client: batches of 16, 10 s query / 120 s batch timeouts, L2 normalization, dimension guard. `fake.embedder.ts` is a deterministic token-hashing embedder for tests. `catalog.config.ts` reads `EMBEDDING_URL`, `EMBEDDING_MODEL` and `EMBEDDING_QUERY_INSTRUCTION`.
- `pdf/pdf-text.ts`: per-page text through `unpdf` (serverless PDF.js, pure JS, no worker or network). Lines are rebuilt from item positions, and wide gaps become ` | `. A page with fewer than 20 non-whitespace characters has no text layer and is skipped. `chunking/chunker.ts`: a pure, page-bounded chunker (about 800 characters, one line of overlap, lines never split).
- `catalog.repository.ts`: the `CatalogRepository` interface and `PrismaCatalogRepository`. It uses tagged-template raw SQL with `::vector` bind parameters. Replacing a document is one transaction: delete by `sourceName`, then insert the document and its chunks. Vector search uses cosine distance filtered by `embeddingModel`. The SKU lookup uses a parameterized `ILIKE ANY` with LIKE wildcards escaped.
- `catalog-ingestion.service.ts`: per file, compute a sha256. If the hash and the model are unchanged and there is no `--force`, the file is `unchanged`. Otherwise extract, chunk and embed everything first, then write once: the file is `ingested` or `replaced`. Corrupt or encrypted files are `failed` and their old chunks are kept. Files with no text at all are `skipped (no_text_layer)`. An embedder failure aborts the run.
- `catalog-search.service.ts` (exported by `CatalogModule` for the budget engine): validates input, embeds the query with the instruction prefix and runs vector top-k. Query tokens matching `[A-Z0-9][A-Z0-9-]{3,}` that contain a digit also run an exact SKU lookup; those chunks rank first with `matchedSku: true`.
- `catalog.controller.ts`: `GET /catalog/search?q=&limit=`.
- `cli/ingest.ts`: compiled to `dist/catalog/cli/ingest.js`. It builds the services by hand, with no HTTP server, and is run by `scripts/catalog/ingest.sh` inside the api image.

Tables: `catalog_document` (unique `source_name`, `content_sha256`, `embedding_model`, `skipped_pages`, `status` `indexed|no_text_layer`) and `catalog_chunk` (`page_number` 1-based, `chunk_index`, `text`, `embedding vector(1024)`, HNSW `vector_cosine_ops`, cascade delete).

## API contract

OpenAPI (`/docs-json`) is the contract for the web PWA and the future native iOS client. Endpoints are documented with `@nestjs/swagger` decorators and DTO classes.

- `GET /health` (`@Public()`): `SELECT 1` raced against a 2 s timeout. 200 `{"status":"ok","database":"up"}` or 503 `{"status":"error","database":"down"}`. Error details are logged by class name only and never returned.
- `GET /catalog/search?q=&limit=`: `q` is 1-500 characters and not blank. `limit` is 1-20 (default 5). The response is 200 `{"query","results":[{chunkId,documentId,catalogName,fileName,pageNumber,text,score,matchedSku}]}` (`results: []` on an empty index). The endpoint returns 400 on invalid input, and 503 `Catalog search is temporarily unavailable` when the embedder or the database is unreachable, with no internals in the body. **Unauthenticated for now**: public partner Catalog content only, and the API binds to 127.0.0.1. Follow-up for `keycloak-realm-roles`: guard the route (signed-in or admin) or remove it, and keep the in-process `CatalogSearchService` as the main consumer. Requires a valid Bearer token (global default-deny `AuthGuard`); `CatalogSearchService` is also used in-process by the budget engine.
- `GET /me` (any realm role): 200 `{sub, username, email, roles}`; 401 without a valid token.
- `GET /admin/ping` (`admin` only): 200 `{"status":"ok"}`; 401 without a valid token, 403 for other roles.
- The OpenAPI document declares the `bearer` HTTP security scheme (`addBearerAuth()` in `configureApp`). Protected controllers carry `@ApiBearerAuth()` and their 401/403 responses. `/docs` and `/docs-json` are served by Swagger outside the Nest router, so they stay public.

- `GET /ai/jobs/:id`: 200 `GpuJobView` (`id`, `kind`, `status`, 1-based `position` and `waitingFor` while queued, ISO timestamps, `errorCode`), 404 unknown or expired, 400 malformed UUID. No product outputs: features expose their own.
- `GET /ai/jobs/:id/events` (SSE, `text/event-stream`): replays the job history, then live events: `queued` (again on every position or blocker change), `running`, then exactly one `done` or `failed`; the stream closes after the terminal event. SSE `id` = per-job `seq` (strictly increasing from 1), `event` = status, `data` = JSON `GpuJobEvent`. `Last-Event-ID: n` sends only `seq > n`. 404 for unknown ids.
- `POST /ai/jobs` (debug only, mounted when `GPU_BROKER_DEBUG_ENDPOINTS=true`, otherwise 404 and absent from OpenAPI): body `{ kind: 'image'|'llm', prompt? }`, runs one adapter call through the broker, 202 `GpuJobView`, 400 invalid body, 429 queue full.
- The job endpoints require a valid Bearer token (global default-deny `AuthGuard`, since `keycloak-realm-roles`); per-job ownership checks arrive with later features (`ownerRef` is stored, not exposed).

## AI layer and GPU job broker (`src/ai/`)

- `jobs/gpu-job-broker.service.ts`: `GpuJobBrokerService` implements the `GpuJobBroker` interface (`submit(kind, run, { ownerRef })` -> `{ jobId, result }`, `get`, `events(jobId, afterSeq)`). Every GPU call goes through `submit`; product features await `result` (rejects with `GpuJobFailedError(code)`). In-process and in-memory: one FIFO queue with head-of-line admission (an image head starts when nothing runs; an LLM head starts when no image runs and running LLM jobs < `llmConcurrency`; no look-ahead). Per-kind timeouts abort the `AbortSignal` passed to the run and free the slot; late settles are ignored. Public errors are codes (`adapter_error`, `timeout`); logs carry the error class name only. Queue cap throws `GpuQueueFullError`. Finished jobs are pruned after `retentionMs`. Jobs are lost on restart.
- `jobs/gpu-residency.hook.ts`: no-op `beforeImage()/afterImage()` around every image job; the GPU stays held until `afterImage` resolves.
- `adapters/`: `LlmAdapter` and `ImageAdapter` interfaces; deterministic fakes (`FakeLlmAdapter` -> `fake:<sha256-16>`, `FakeImageAdapter` -> `fake/<sha256-16>.png`; optional `delayMs` or `gate`, abort-aware, `active`/`maxActive`/`calls` for tests); `LlamaServerLlmAdapter` (non-streaming `POST /v1/chat/completions`, `response_format: json_schema` when a schema is given, non-2xx -> `AiBackendError(status)` without the body). The real ComfyUI adapter arrives with `controlnet-render`.
- `ai.tokens.ts`: `LLM_ADAPTER`, `IMAGE_ADAPTER`, `GPU_BROKER_OPTIONS`, `AI_ENDPOINTS`. `ai-endpoints.provider.ts`: `AiEndpointsProvider.get()` (env-backed today, read per call; `admin-service-endpoints` backs it with Platform Settings).
- Env (read at module build): `AI_ADAPTERS` (`fake` default, `local` = llama-server LLM, image still fake), `LLM_BASE_URL` (`http://llama-server:8080`), `COMFYUI_BASE_URL` (`http://comfyui:8188`), `GPU_BROKER_DEBUG_ENDPOINTS` (`false`), `GPU_BROKER_LLM_CONCURRENCY` (1), `GPU_BROKER_MAX_QUEUED` (20); code defaults only: `GPU_BROKER_IMAGE_TIMEOUT_MS` (180000), `GPU_BROKER_LLM_TIMEOUT_MS` (120000), `GPU_BROKER_RETENTION_MS` (3600000), `AI_FAKE_IMAGE_DELAY_MS` (3000), `AI_FAKE_LLM_DELAY_MS` (500).

Overridden templates: `template.ftl` (wordmark header, intro, form-level alert, no language picker), `login.ftl`, `register.ftl`, `email-code-form.ftl` (provider template), `error.ftl`, `info.ftl`, `login-page-expired.ftl`, and the provider's `code-email.ftl` (`email/html` + `email/text`). Other Keycloak pages fall back to base markup with the `kc*Class` mappings in `login/theme.properties`. Messages: `login/messages` and `email/messages`, 11 `messages_<locale>.properties` each; they override the Keycloak and provider keys shown on the designed pages. The realm enables self-registration (flow `registration-email-otp`: a copy of the built-in registration form, then `email-authenticator-no-enrollment` REQUIRED), adds `user` to the default role `default-roles-bricomission` (imported seeded users keep only their listed role), turns on internationalization (the 11 locales, default `en`; pages and the code email follow `ui_locales`; the register page stores no Keycloak `locale` on new accounts, because a stored locale would beat `ui_locales`) and sets the SSO idle timeout to 8 h (max stays 10 h). `./init.sh` fetches the dev client's sign-in page and fails with the realm reset command when the theme stylesheet is missing (stale realm volume), and does the same when the authorization URL of `bricomission-web` is rejected (realm imported before `homeowner-password-login`).

The web image is multi-stage: `pnpm install --frozen-lockfile --filter @bricomission/web...`, `next build` (`output: 'standalone'`, `outputFileTracingRoot` = repo root), then a runtime stage with `.next/standalone`, `.next/static` and `public`, running `node apps/web/server.js` as user `node` (`HOSTNAME=0.0.0.0`, `PORT=3000`, telemetry off). Env `API_INTERNAL_URL=http://api:3000` and, for sign-in, `WEB_DATABASE_URL` (same database and credentials as the api, no `?schema`; every query is schema-qualified), `WEB_PUBLIC_URL=http://localhost:$WEB_PORT`, `KEYCLOAK_PUBLIC_URL=http://localhost:$KEYCLOAK_PORT`, `KEYCLOAK_INTERNAL_URL=http://keycloak:8080`, `KEYCLOAK_WEB_CLIENT_SECRET` (`BM_WEB_CLIENT_SECRET`) and `WEB_SESSION_KEY` (dev defaults in compose and `.env.example`); healthcheck fetches `/manifest.webmanifest`; no `depends_on` (Home reports the API state itself and works anonymously with postgres or Keycloak down). Keycloak gets `BM_WEB_PUBLIC_URL` and `BM_WEB_CLIENT_SECRET` for the `${...}` placeholders of the `bricomission-web` client (secret, `rootUrl`/`baseUrl`, redirect URI `.../auth/callback`, post-logout URI, `webOrigins: []`, the `bricomission-api` audience mapper); the placeholders resolve outside `credentials` too. `web-e2e` mounts the repo at `/repo` (workdir `apps/web`, `HOME=/tmp`), uses `network_mode: host` (installability needs a `localhost` secure context) and `ipc: host`, and runs as the calling user.

The api image is multi-stage: frozen install, `prisma generate` + `tsc`, then `pnpm deploy --prod --legacy` into a runtime stage that runs as user `node`. Build context is the repo root (`.dockerignore`). The api waits for postgres to be healthy and has its own `/health` healthcheck.
