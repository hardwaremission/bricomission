# Context

Shared vocabulary for BricoMission. Definitions only: decisions live in `docs/`, rules in `docs/domain-model.md`.

## Glossary

### Homeowner
A person who plans a kitchen renovation in the app. Holds the **User** role. Anonymous until the Login Gate.

### Professional
A person who works for a Company and bids on Dossiers. Holds the **Professional** role. Every Professional belongs to exactly one Company.

### Company
The business entity that groups Professionals and owns Bids. Identified by a Tax ID. A self-employed contractor (autónomo) is a Company with one member.

### Tax ID
Spanish fiscal identifier of a Company: CIF for companies, NIF for self-employed contractors. Format-validated by the system, verified manually by an Administrator.

### Administrator
Internal platform operator. Holds the **Administrator** role and uses the Admin Dashboard.

### Kitchen Project
A Homeowner's renovation case: photos, measurements, moodboard, renders, budget, and its path (DIY or Marketplace). Called "obra" by Professionals.

### Measurements
Manual room dimensions (length × width × height) entered by the Homeowner.

### Moodboard
The set of reference images a Homeowner selects to express the target style. Made of Moodboard Items; at most 12 per Kitchen Project.

### Moodboard Item
One image in a Moodboard: either a picked Style Gallery image or an own reference photo the Homeowner uploaded. Selecting a gallery image adds an item; tapping it again removes it.

### Style Gallery
The curated, fixed set of example kitchen images (8 styles x 3) a Homeowner picks from to build a Moodboard. Committed to the repository and served offline; never generated at runtime.

### Render
A photorealistic image generated by ControlNet from one Homeowner Photo plus the dominant Moodboard style, preserving the room geometry (windows, doors, plumbing). Each Render keeps its **before** image: the exact centre crop of the Photo that the image model received, so before and after align pixel for pixel. Own reference uploads in the Moodboard do not guide the style yet.

### Budget
The priced bill of materials for a Kitchen Project. Has four Budget Tiers. Totals are always computed by code, never by the LLM.

### Budget Tier
One of four pre-computed budget levels: Luxury, High, Medium, Low.

### Line Item
One entry of a Budget: product, SKU, source catalog, cited unit price, quantity, computed subtotal.

### Catalog
A partner product catalog (IKEA, Leroy Merlin, BricoDepot) ingested from PDF into the local RAG index.

### Persona
One of four switchable assistant personalities that change the chat system prompt: Strict Foreman, Empathetic Designer, Frugal Friend, Neutral Assistant.

### Prompt Macro
A UI control (button, dropdown) that sends a structured hidden prompt to the budget chat instead of running its own math.

### DIY Path
Outcome where the Homeowner downloads a Shopping List PDF and buys/installs the materials personally.

### Shopping List
The exact, executable list of products, SKUs, quantities, and prices for the DIY Path, exported as PDF.

### Marketplace Path
Outcome where the Homeowner publishes a Dossier to receive Bids from Companies.

### Dossier
The locked, fully specified package of a Kitchen Project (renders, measurements, chosen materials, Budget) published to the Marketplace. Immutable once published.

### Bidding Window
Time during which a Dossier accepts Bids. 15 days by default; duration configurable by the Administrator.

### Bid
A Company's offer on a Dossier: price, guaranteed installation date, delay penalty per day. One Bid per Company per Dossier. Shown anonymously to the Homeowner.

### Contract
The binding PDF generated when a Homeowner accepts a Bid. Includes delay penalties and the Platform Commission. Becomes binding when both parties complete Electronic Acceptance.

### Electronic Acceptance
Simple electronic signature: re-authentication plus a recorded evidence entry (who, when, IP, SHA-256 of the Contract PDF).

### Platform Commission
Success fee the Company owes BricoMission for an accepted Contract. Percentage set by the Administrator.

### Payment Mode
Admin switch for commission checkout: Simulated (offline, records a pending commission) or PayPal Sandbox.

### Energy / Daily Quota
Per-user daily limit of LLM calls and image generations, enforced only when the global Quota Flag is on. Admin can override it per user or reset a user's daily counter.

### Login Gate
The point where an anonymous Homeowner must sign in: right before the first costly AI call (Render or Budget). It lives on the Generate step: "Generate my kitchen" or "Get my budget" opens a sheet with Sign in / Create account. After the sign-in the browser's draft Kitchen Project is **claimed**: the same project (same id, photos, Measurements, Moodboard) is bound to the Account and stops expiring (`login-gate-claim`).

## Rejected / Ambiguous Terms

### "Project" (bare)
Use `Kitchen Project`. Reason: collides with the software project and with GitHub projects.

### "Presupuesto" for a Professional's offer
Use `Bid`. Reason: `Budget` is the Homeowner's priced bill of materials; a Professional's offer is a different object.

### "CIF" as the field name
Use `Tax ID`. Reason: self-employed contractors have a NIF, not a CIF.

### "User" for any account
Use `Homeowner`, `Professional`, or `Administrator`. "User" only names the B2C role in Keycloak.

### "NotebookLM knowledge base" at runtime
Use `Catalog` (local RAG index). Reason: NotebookLM has no runtime API; it is not part of the running system.
