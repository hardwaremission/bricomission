# Feature Implementation Spec: Presenter watches a live blueprint-style diagnostics dashboard of the whole architecture

## Source Feature

- `id`: diagnostics-dashboard (issue #31)
- `area`: observability
- `depends_on`: simulations-ux-overhaul (accepted)
- `status`: not_started at planning time (2026-11-15); set to `in_progress` by the planner
- `source`: `feature_list.json` (verification list and notes are developer decisions, settled), PRD section 9 (DD-1 to DD-7), PRD section 8 (demo); branch `feature/diagnostics-dashboard`
- This feature closes the MVP (deadline 2026-11-22; every other feature is phase 2). By developer decision it stays one feature although it is far over the 250-line target and spans one new runtime pipeline, two new apps and a design. See "Phasing" and "Cut order".

## Goal

A separate desktop web (own container, own URL `http://localhost:3200`, no login, 127.0.0.1 only) that explains the whole architecture by itself. It draws every container and every API module as a node of an Unreal-Engine-blueprint-style graph (typed pins, curved edges). When something runs, the edges between the working nodes light up and animate, then fade. Beside the graph a collapsible log narrates line by line which node starts a communication, towards which node, and what it sends or receives (the budget prompt, the style prompt built from several images, ...). Every container node has a CPU %, RAM, VRAM and GPU % widget; AI nodes name their model; one global legend explains everything. Diagnostic only: it never changes app state and never calls an AI endpoint. In the demo the portrait app sits in one browser window and the dashboard in another.

## Non-Goals

- OpenTelemetry, Jaeger, Prometheus, a persistent event store, history beyond the memory ring buffer, alerting, per-user filtering, authentication of the dashboard.
- Browser-side instrumentation code in the PWA (the web BFF sees every browser request; see Decision 12).
- Per-API-module CPU/RAM/VRAM/GPU attribution (modules share one process; see Decision 9 and OQ-2). Metrics for non-AMD GPUs beyond "n/a".
- Controlling the stack from the dashboard (start/stop/restart, toggles), cloud fallback views, the Admin panel, native iOS.
- Localization of the dashboard (English only, OQ-4). Mobile or portrait layout of the dashboard.
- Changing any product behavior, contract or response of the app. The OpenAPI document does not change (diagnostics routes are hidden).

## Phasing (one branch, one PR, nothing committed until accepted)

A: spikes (amdgpu per-container mapping, SSE through the stack plus async context through the broker, graph library offline). B: shared types, event core and the API endpoints. C: instrumentation (adapters, storage, Prisma, broker, residency, runner, budget, web BFF). D: metrics agent container. E: diagnostics app (blocked until the design read-back exists). F: compose, launch-demo, init, replay, E2E, real-GPU run, docs, ADR 0006.
Phase N+1 may not start before phase N is green, except that the design (orchestrator with the developer in OpenPencil) should run in parallel with A to D so that E is not blocked. If A1 shows per-container GPU percent cannot be measured, use the approximate fallback of Decision 7 and continue. If A3 fails (library not usable offline or too slow), stop and report: the orchestrator decides (custom SVG renderer, OQ-5 fallback) before phase E.

## Decisions

Settled by the developer (do not reopen):

1. Separate app and container `diagnostics`, port `DIAGNOSTICS_PORT` (default 3200) bound to `127.0.0.1:${DIAGNOSTICS_PORT:-3200}:3000`, Compose profile `diagnostics`, no login. `launch-demo.sh` starts it by default (Decision 15).
2. Two node levels: containers plus the API internal modules, grouped like Unreal comment boxes. The real lists are in "Node Catalog".
3. Own lightweight event bus: a correlation id on every request, events `{id, ts, correlationId, from, to, kind, summary, payload}` over SSE, memory ring buffer with replay on connect. No OpenTelemetry or Jaeger.
4. Privacy: prompts in full (expandable when long), images only as thumbnails or sizes, never tokens, cookies, secrets, passwords or image bytes. A pure redaction helper with tests. The SSE endpoint exists only when `DIAGNOSTICS_ENABLED=true` and needs a shared token.
5. Metrics agent: a read-only container in the same profile (`pid: host`, `/sys` and the Docker socket read-only). Privileges documented honestly in ADR 0006 and the risks table.
6. Visual: dark blueprint look, `@xyflow/react` (React Flow, MIT, exact pin, bundled so it works offline), typed pins, curved animated edges that light while a communication is in flight and fade after, desktop 1920x1080, designed first by the orchestrator in new file `design/openpencil/bricomission_diagnostics.fig`, read-back `docs/design/diagnostics-dashboard.md` (the orchestrator creates it; phase E is blocked without it).

Planner decisions (each justified by the repository):

7. **GPU and per-container metrics.** The agent samples every 1000 ms. CPU and RAM: cgroup v2 files of each container scope (`cpu.stat` `usage_usec` delta, `memory.current` minus `memory.stat` `inactive_file`, as `docker stats` does). The container-to-PID mapping uses `/proc/<pid>/cgroup` (`docker-<64 hex>.scope`; the agent runs with `cgroup: host` so paths are not namespaced) and `cgroup.procs`; the container-to-node mapping uses the label `com.docker.compose.service` read once per 5 s with `GET /containers/json` on the Docker socket (plus `State.Health` for node state). GPU: for every PID of a container, fds that read-link to `/dev/dri/renderD*` or `/dev/kfd`, then `/proc/<pid>/fdinfo/<fd>` lines `drm-driver: amdgpu`, `drm-client-id`, `drm-memory-vram` (KiB), `drm-engine-gfx` and `drm-engine-compute` (ns); distinct `drm-client-id` summed per container. VRAM = that sum; GPU % = delta of (gfx + compute) engine ns over wall ns, clamped at 100 (ROCm kernels run on the compute queue, so gfx alone would read 0 for llama-server and ComfyUI; spike A1 confirms which counters move). Fallbacks, in order: `/sys/class/kfd/kfd/proc/<pid>/vram_<gpu_id>` for VRAM; global `/sys/class/drm/card*/device/gpu_busy_percent` split by VRAM share with `approx: true`. Host totals: `mem_info_vram_used|total` (the same file `scripts/ai-spike/vram-sample.sh` reads), `/proc/meminfo`, `/proc/stat`. CPU % is shown as a share of all host threads (32) with the raw core count in text.
8. **Placement and framework (ADR 0003 and the web app).** `apps/diagnostics` (`@bricomission/diagnostics`): Next.js 16 App Router, React 19, Tailwind 4, `@xyflow/react`, standalone output, same toolchain and Dockerfile pattern as `apps/web`; its route handlers are the server-side proxy. `apps/diagnostics-agent` (`@bricomission/diagnostics-agent`): plain Node, TypeScript compiled by tsc, no runtime dependencies (stdlib only), `node:26.13.1-bookworm-slim`. No new shared runtime package: event, metric and node-id types are added to `packages/shared-types` (type-only, as today); the redaction helper and ring buffer live in `apps/api/src/diagnostics/`; the web BFF sends only metadata it builds itself, and the API re-validates and re-redacts every ingested event.
9. **Module widgets.** API modules share one process, so a module widget shows the API container's values labelled "api container (shared)" plus module-specific live counters (spans in flight, events per minute, queue length for the broker). Honest, and never a fabricated per-module split (OQ-2).
10. **Reaching the API and the agent.** All on the compose network, no CORS, no token in the browser. The diagnostics server (`apps/diagnostics`) connects to `http://api:3000/diagnostics/stream` with header `X-Diagnostics-Token` and to `http://diagnostics-agent:3300/metrics/stream` with the same header (agent has no published port), merges them with its own probes (Mailpit poll) and re-serves one SSE stream to the browser at `/stream` (same origin). The browser `EventSource` therefore needs no headers and reconnects natively.
11. **Token and default-deny.** `DiagnosticsModule.register()` is imported by `AppModule` and mounts its controller only when `DIAGNOSTICS_ENABLED === 'true'` and `DIAGNOSTICS_TOKEN` has at least 16 characters; otherwise every `/diagnostics/*` route is a plain 404 and a `NullDiagnostics` (field `enabled = false`, no-op `emit`) is provided. The controller is marked `@Public()` (opts out of the JWT `AuthGuard`, so it never accepts a Keycloak token) and `@UseGuards(DiagnosticsTokenGuard)`: header `X-Diagnostics-Token` only (never a query string), compared as SHA-256 digests with `timingSafeEqual`; missing or wrong gives the generic 401 (no `WWW-Authenticate`), logs carry no token. A test proves the controller is `@Public()` and every handler is denied without the token, so default-deny still holds for everything else. Routes use `@ApiExcludeController()` and stay out of `openapi.json` (no client codegen, no drift). Dev default `DIAGNOSTICS_TOKEN=bm-diagnostics-dev-token` in compose and `.env.example`, same policy as the other dev secrets.
12. **Correlation.** `X-Correlation-Id` (16 hex chars) is minted by the web BFF for every `/api/*` and `/auth/*` request it handles (the browser cannot be trusted and a PWA-side fetch wrapper adds client code and a service-worker concern); a valid browser-sent value is kept (OQ-1). The BFF forwards it upstream (add to the proxy's forwarded headers, only when enabled), the API middleware validates it (else mints) and stores it in an `AsyncLocalStorage`. The broker captures the context at `submit` and re-enters it in `start` (a job can be started from another job's `finish`, which would otherwise leak the wrong id). Background work started in a request keeps the context through the promise chain. Boot-time work (recovery, sweeper) uses correlation id `system`.
13. **Event model.** `DiagnosticsEvent = { id, ts, correlationId, from, to, kind, summary, payload, span?, durationMs?, ok?, simulated?, inferred?, poll? }`. `id` is the numeric sequence as a string (also the SSE `id`). `from`/`to` are node ids; `from === to` is a self event (node glows, no edge). `span: { id, phase: 'start'|'end' }` pairs a request with its response: the edge is active while a span is open, a response lights the reverse direction, and the edge fades `EDGE_FADE_MS` (1500) after its last event (minimum visible 600 ms so a 20 ms hop is seen). `simulated: true` marks events produced by the fake adapters (drawn with a dashed edge and a legend entry; the demo can run without the GPU and still shows the whole path). `poll: true` marks high-frequency status polling (the web polls Simulation and Budget status every 2 s): coalesced into one log row with a counter, drawn at low intensity. Parallel identical-shape events inside 150 ms (the 8 concurrent catalog queries) coalesce into one expandable group row.
14. **Buffer and size.** Ring buffer bounded by bytes (`DIAGNOSTICS_BUFFER_MAX_MB`, default 32, oldest evicted) and by count (`DIAGNOSTICS_BUFFER_SIZE`, default 3000). Text fields are cut at 64 KB with `{truncated: true, originalBytes}` (the full budget prompt is 10-20 KB and must pass), total payload at 96 KB, arrays at 50 items, depth 6. Replay on connect sends the whole buffer (query `replay=N` for the last N).
15. **launch-demo.sh.** Starts diagnostics by default (the demo needs it); `--no-diagnostics` skips it. The script exports `DIAGNOSTICS_ENABLED=true` for every compose call (each `docker compose up` recreates `api` and `web`, so the flag must be on all of them, including the final `AI_ADAPTERS=local docker compose up -d --wait api`), starts `--profile diagnostics`, prints the dashboard URL and the two-window layout, and stops the two services on exit (`--keep-core` also stops them and recreates api and web with `DIAGNOSTICS_ENABLED=false`).
16. **Replay and synthetic traffic.** The diagnostics server can serve a recorded session instead of the live sources: `/stream?source=replay` (or env `DIAGNOSTICS_SOURCE=replay`) plays `apps/diagnostics/replay/demo-simulation-budget.ndjson` (events and metric samples recorded from a fake-adapter Simulation plus Budget by `scripts/diagnostics/record-replay.sh`, already redacted, original timing, `speed` query). The header shows a fixed `REPLAY` badge so it is never mistaken for live. Uses: design review, rehearsal of the two-window layout, E2E of the UI without the API, GPU-less screenshots.
17. **Node state** (from the agent's Docker state plus event traffic): `idle`, `working` (a span is open or an event arrived in the last 600 ms), `error` (the last event has `ok: false`, or the container is `unhealthy`/`exited`; cleared by the next ok event), `disconnected` (no agent data for 5 s or container absent; the graph keeps working).
18. **Modules are data.** `apps/api/src/diagnostics/topology.ts` is the single source of node ids, labels, groups, kinds, pins, structural edges and model names. `GET /diagnostics/topology` serves it (models read from real config, never hard-coded in the dashboard); the dashboard keeps only layout positions keyed by id (`apps/diagnostics/src/graph/layout.ts`); a test fails when an id has no layout or a layout id is unknown.

## Job Story

When I present BricoMission with the app in a portrait window and the dashboard in another, I want every request to visibly travel through the architecture with its prompt and its model named, so the audience understands how the whole system works without a narrator explaining the boxes.

## Users And Permissions

No login (developer decision), localhost only; it therefore shows every user's prompts and project metadata and is meant for the presenter's machine (risk row). The API stream, topology and ingest routes need `X-Diagnostics-Token` and exist only when enabled. The agent has no published port and checks the same header. Nothing in the dashboard can write to the app.

## API Contract

All routes below are hidden from OpenAPI and absent (404) unless `DIAGNOSTICS_ENABLED=true`. Header `X-Diagnostics-Token` on every one.

- `GET /diagnostics/stream` (SSE): first `event: hello` `{bootId, enabled: true, adapters: 'fake'|'local', oldestSeq, newestSeq, bufferCount}`, then the replay, then live `event: diagnostics` with `id: <seq>`, `data: DiagnosticsEvent`. `Last-Event-ID: n` sends only `seq > n` (if the `bootId` changed the client discards state). `: ping` every 15 s. 401 without a valid token.
- `GET /diagnostics/topology` -> `{ bootId, groups, nodes: [{id, label, group, kind, pins, models: [{role, name}]}], edges: [{id, from, to, kind, fromPin, toPin}] }`.
- `POST /diagnostics/ingest` (web BFF): JSON array of at most 100 events, body at most 256 KB, at most 200 events per second; every event is validated (known node ids, kind enum, string lengths), re-redacted and given a server sequence. 204; 400 invalid; 413; 429. The web emitter is fire-and-forget (batch of 20 or 250 ms, one attempt, drops and counts on failure, never blocks a request).
- Agent (internal port 3300): `GET /metrics/stream` (SSE, 1 sample per second), `GET /metrics` (last sample), `GET /topology` (`capabilities: {cgroupV2, amdgpuFdinfo, kfdSysfs, dockerSocket}` and the model files parsed from the read-only `llama-models.ini`: `model` and `mmproj`). Sample: `{ts, host: {cpuPct, ramUsedMiB, ramTotalMiB, vramUsedMiB, vramTotalMiB, gpuBusyPct}, containers: {[nodeId]: {state: 'running'|'unhealthy'|'exited'|'absent', cpuPct, cores, ramMiB, vramMiB, gpuPct, approx?}}}`.
- Diagnostics server (public on 127.0.0.1:3200): `/` (dashboard), `/stream` (merged SSE: `hello`, `event`, `metrics`, `status` frames), `/api/topology` (proxy), `/api/health`. Mailpit probe: `GET <MAILPIT_URL>/api/v1/messages?limit=10` every 2 s reading only `ID`, `Created`, `Subject`, masked `To` (never `Snippet` or body).
- Env: `DIAGNOSTICS_ENABLED` (false), `DIAGNOSTICS_TOKEN`, `DIAGNOSTICS_PORT` (3200), `DIAGNOSTICS_BUFFER_SIZE`, `DIAGNOSTICS_BUFFER_MAX_MB`, `DIAGNOSTICS_SOURCE` (live|replay), web gets `DIAGNOSTICS_INGEST_URL=http://api:3000/diagnostics/ingest`.

Groups (comment boxes, left to right): **Client** (browser), **Web container** (web), **API container** (box titled "API (NestJS)" with the container widget in its header; sub-boxes Request layer, Generation, Budget, GPU scheduling, Infra clients), **Identity and mail** (keycloak, mailpit), **Data** (postgres, minio), **AI inference** (llama-server, comfyui, embedder). Pin types: exec/flow (white), `http` blue, `sql` green, `object` amber, `llm` violet, `image` pink, `embed` teal, `auth` cyan, `mail` grey, `queue` white outline. Every node has one in pin and one out pin per kind it uses.

Containers (kind `container`; metrics widget; models from config):
- `browser` Browser PWA (kind `client`, widget "n/a: client device").
- `web` Next.js web / BFF.
- `keycloak` Keycloak (realm BricoMission), `postgres` PostgreSQL 17 + pgvector, `minio` MinIO, `mailpit` Mailpit.
- `llama-server` llama.cpp router (kind `ai-gpu`): `Qwen3-VL-30B-A3B-Instruct Q4_K_M` plus mmproj `Qwen3-VL-30B-A3B-Instruct-mmproj-F16` (router id `qwen3-vl`, experts on CPU `--n-cpu-moe`); from `llama-models.ini` through the agent and live `GET /v1/models`, falling back to `LLM_MODEL`.
- `comfyui` ComfyUI (kind `ai-gpu`): checkpoint `RealVisXL_V5.0_fp16`, ControlNet `sdxl-canny` and `sdxl-depth`, IP-Adapter `ip-adapter-plus_sdxl_vit-h`, CLIP vision `CLIP-ViT-H-14-laion2B-s32B-b79K` (exported constants of `comfyui-workflow.ts`, so the dashboard cannot drift from the workflow).
- `embedder` llama.cpp CPU embedder (kind `ai-cpu`): `Qwen3-Embedding-0.6B Q8_0` (env `EMBEDDING_MODEL` and the compose command).
- The API container is the box `api`; the dashboard itself and `web-e2e` are not nodes.

API modules (kind `module`, derived from `apps/api/src`):
- `api-guards` HTTP entry and guards (`AuthGuard` JWT, `RolesGuard`, `DraftTokenGuard`, `OwnedProjectGuard`); the only ingress target of web.
- `project-service` Kitchen Projects (drafts, claim, owner edits, Moodboard, sweeper). `image-pipeline` photo processor, crop, render encode, 768 px scaling (`sharp`, HEIC). `style-gallery` Style Gallery assets (disk).
- `simulation-runner` Simulations and Renders (`SimulationsService`, `SimulationRunner`, `RendersService`). `style-engine` calculated style (weights, merge, prompts, `calculated-style.ts`, `style-traits.ts`, `render-prompt.ts`).
- `budget-engine` Budget pipeline (inventory, retrieval, pricing attempts). `budget-math` verify and compute (`budget-extraction`, `budget-math`, `tier-order`, `price-bands`; ADR 0002). `catalog-search` Catalog RAG search.
- `gpu-broker` GPU job broker. `residency-hook` GPU residency hook. `ai-adapters` AI abstraction layer (shows `fake` or `local`).
- `storage-client` Object storage client (S3). `data-access` Prisma data access.

Structural edges (each lights from its events): browser>web, web>api-guards, web>keycloak, web>postgres, api-guards>keycloak (JWKS), api-guards>{project-service, simulation-runner, budget-engine, catalog-search, style-gallery}, project-service>{image-pipeline, storage-client, data-access}, image-pipeline>storage-client, simulation-runner>{style-engine, style-gallery, image-pipeline, storage-client, data-access, gpu-broker}, budget-engine>{catalog-search, budget-math, gpu-broker, storage-client, data-access}, catalog-search>{embedder, data-access}, gpu-broker>{residency-hook, ai-adapters}, residency-hook>llama-server, ai-adapters>{llama-server, comfyui}, storage-client>minio, data-access>postgres, keycloak>mailpit. Responses light the same edge in reverse.

## Event Catalog

Kinds: `http`, `auth`, `guard`, `sql`, `object`, `llm`, `image`, `embed`, `queue`, `residency`, `step`, `compute`, `mail`, `session`. Each row: from > to, kind, summary, payload (response in the `end` span event), edge animation. Payload never has tokens, cookies, headers, secrets, `styleSeed`, image bytes.

1. browser > web, `http`: `GET /kitchen-projects/:id/results`, `POST /api/kitchen-projects/:id/simulations`; method, route template, status, bytes, locale, ms. Emitted by the BFF on arrival and completion; pulse browser>web, active until the response.
2. web > api-guards, `http`: forwarded route; `hasSession`, `hasDraftToken` (booleans), upstream status, ms; `poll` for status polling.
3. web > keycloak, `auth`: `code exchange`, `refresh token` (30 s before expiry), `logout backchannel`, endpoint path, grant type, status, ms. web > postgres, `session`: `web_session lookup/insert`, table, rows, ms.
4. api-guards > keycloak, `auth`: `JWKS fetch (cache miss)`, path, status, ms (only when the remote key set refetches).
5. api-guards > {target module}, `guard`: `jwt ok role=user owner ok` with route template, role names, `sub` as an 8-char hash; target chosen by `route-node-map.ts` (simulations -> simulation-runner, budget -> budget-engine, drafts/photos/moodboard/claim/edits -> project-service, `/catalog/search` -> catalog-search, `/style-gallery` -> style-gallery); end event carries status and ms. Denials: `ok: false`, status 401/403/404/409/429.
6. data-access > postgres, `sql`: `Simulation.create`, `PlatformSetting style_blend_mode = both`, `catalog vector search (HNSW cosine, top 5)`: model, operation, rows, ms, never parameters; coalesced per correlation, operation and 250 ms (`count`). Vector search carries hits `[{catalog, page, score, sku?}]`.
7. image-pipeline > storage-client > minio, `object`: `process photo` (type, size in, `full`/`thumb` sizes, thumbnail), `PUT kitchen-projects/<id>/photos/<id>/full.jpg`, `put before/full/thumb.jpg` of a Render, `get`, `deleteMany (n keys)`: key, bytes, ms.
8. simulation-runner > style-engine, `compute`: `weights gallery-modern 31 %, upload 1 42 % ...` (mode, isFirst, percentages, reference thumbnails); `merged traits text (<= 160 chars)` with the text and keywords; `style_degraded` fallback when the vision step fails.
9. simulation-runner > gpu-broker, `queue`: `submit llm job (describe n references)`, `submit image job k of N`; then broker events from the existing `GpuJobEvent`: `queued position p waitingFor image`, `running`, `done`/`failed` with short job id and ms. Pulse; stays active until `done`.
10. gpu-broker > residency-hook, `residency`: `beforeImage: unload LLM`, `beforeLlm: nothing (ComfyUI stays warm)`; residency-hook > llama-server, `http`: `POST /models/unload {model: qwen3-vl}`, status, ms; then a `step` self event on llama-server when the next llm job reloads it (`LLM reload (cold), ~7 s`, tracked by one flag in the hook).
11. gpu-broker > ai-adapters, `queue`: `run job <kind>`; ai-adapters > llama-server, `llm`: `chat completion task=style_traits|inventory|budget` with model name, messages in full (text expandable, images as thumbnails with sizes), schema name, `maxTokens`; end: reply text (full, expandable), prompt and completion tokens, tok/s, ms. This is where the budget prompt (system, user, retrieved chunks, inventory, bands, retry feedback) and the multi-image style description are shown.
12. ai-adapters > comfyui, `image`: `upload input + n references`, `POST /prompt` (blend mode, size, positive prompt = calculated style text in full, negative prompt, ControlNet mode canny/depth with strength and end, IP-Adapter weights per reference with thumbnails, model names), `poll` (coalesced), `view`; end: seconds, output size, result thumbnail. With fake adapters the same events fire with `simulated: true` and `model: fake:<hash>`.
13. simulation-runner, `step` (self and edges): `describing (n references)`, `rendering k of N`, `retry render k (attempts 2)`, `finished: succeeded|partial|failed`. Drives node `working` and the narrated progress.
14. budget-engine > catalog-search, `step`: `8 base queries x 5 hits` (queries listed), later `+k extra queries from the inventory`; catalog-search > embedder, `embed`: `POST /v1/embeddings` query text, dimensions 1024, ms (group of 8); catalog-search > budget-engine: `results: n chunks, top score`.
15. budget-engine > gpu-broker (`queue`) and via ai-adapters > llama-server (`llm`, task `inventory`, render thumbnail): `Reading image n of N`, merged inventory (category, max count) as a `compute` self event of budget-engine.
16. budget-engine > budget-math, `compute`: `verify and compute attempt a of 3`: items accepted or rejected with reasons (price not on the cited SKU line), per tier subtotal/VAT/total in cents, `isStrictlyOrdered` true/false, `relabeled`; budget-math > budget-engine returns the verified tiers. Teaches ADR 0002: the model extracts, code computes.
17. keycloak > mailpit, `mail`, `inferred: true`: `email code sent to b***@example.com`, subject only (the diagnostics server polls Mailpit; never the code or body).
18. project-service > storage-client / data-access, `step`: `claim draft`, `sweeper deleted n expired drafts` (correlation `system`).
Errors: any failed span ends with `ok: false`, summary `failed (timeout|adapter_error|storage_unavailable|...)`, edge red for 3 s, node `error`.

## Acceptance Scenarios

1. **Disabled by default.** Given `DIAGNOSTICS_ENABLED` unset, `GET /diagnostics/stream` and `/topology` are 404, no wrapper is installed, the OpenAPI snapshot is byte-identical, and a Simulation runs with no event allocated (test spies on `NullDiagnostics`).
2. **Token.** Enabled: no token, wrong token, token in the query string and a valid Keycloak JWT all give 401; the right header streams; a token shorter than 16 characters keeps the module off.
3. **Stream.** Events arrive in sequence order with correlation ids, `hello` first, replay on connect, `Last-Event-ID` resumes, a second client gets the same buffer, the ring buffer evicts by bytes and count, a 20 KB prompt passes whole, a 200 KB field is truncated with its marker.
4. **Demo path (fake adapters).** A signed-in owner runs a Simulation (3 photos, 2 references) and then a Budget on the kitchen test app: every row of the Event Catalog that applies to the fake stack appears in order under one correlation id per request, `simulated: true` on the llama-server and comfyui hops, the real prompts and the style text present, thumbnails but no image bytes.
5. **Redaction.** A fuzz table (nested tokens, `Bearer`, JWT shapes, cookies, `bm_session`, `bm_draft`, `X-Draft-Token`, passwords, `client_secret`, S3 keys, OTP `code`, Buffers, `data:` URIs, errors with `cause`, emails) never appears in any emitted event; prompts and style text are preserved verbatim.
6. **Metrics.** Recorded samples map PIDs to containers and nodes, sum distinct `drm-client-id`, compute CPU % and GPU % from deltas, handle a counter reset, a missing fdinfo (fallback `approx`), non-AMD (`n/a`), and sum host totals; during a real-GPU Simulation the llama-server and comfyui widgets show non-zero VRAM and GPU %.
7. **Dashboard (E2E 1920x1080, fake adapters).** Running a Simulation and a Budget in the app lights the edges in order, log lines name source, destination, kind and payload, the log collapses and expands while edges keep animating, AI nodes show model names, every container widget and the legend render, `REPLAY` is absent in live mode.
8. **Resilience.** API restart or stream drop: header goes `RECONNECTING`, nodes keep their last state, a gap marker row appears, the stream resumes; agent down: widgets show `no data`; no `amdgpu` counters: VRAM and GPU show `n/a`.
9. **Cold start and exposure.** `./launch-demo.sh --fake` and `docker compose --profile diagnostics up` bring the dashboard up on `127.0.0.1:3200` without login; it does not answer on another interface; the agent has no published port.

### Findings
- The broker already emits per-job `GpuJobEvent` (`queued|running|done|failed`, position, waitingFor) from one `emit()`; the residency hook is a 5-method class with one real behavior (`beforeImage` unload); both are one-line seams.
- `LLM_ADAPTER`, `IMAGE_ADAPTER`, `OBJECT_STORAGE`, `EMBEDDER` and `PrismaService` are provider-factory seams: a decorator can be applied at composition time, so `DIAGNOSTICS_ENABLED=false` installs nothing.
- Prompts live in `LlmRequest.messages` (text or image parts) and `ImageRequest.prompt/negativePrompt/references`; the budget prompt is stored on the `budget` row but never returned, so the adapter wrapper is the right capture point.
- The web proxy forwards a fixed header allowlist: `x-correlation-id` must be added (only when enabled). The proxy and `GET /health` poll constantly: polling needs `poll` coalescing.
- Keycloak sends the code email itself; the API never sees it, so that hop is inferred from Mailpit.
- Containers run under the compose project name: the agent must filter by `com.docker.compose.project` (parallel worktrees use other names).
- The stack already runs on Node 26; the API is tsc-built ESM (`.js` import suffixes); the agent follows the same build pattern.
- Not verified (spikes): which amdgpu fdinfo counters move for ROCm in containers on this kernel (7.3.3-1-cachyos), whether `SYS_PTRACE` is needed for foreign-uid fdinfo, cgroup path layout with `cgroup: host`, Next route-handler SSE buffering, `@xyflow/react` frame rate with about 25 animated edges.

- **Compose** (`compose.yaml`): `diagnostics` (build `apps/diagnostics/Dockerfile`, profile, `127.0.0.1` port, env `API_INTERNAL_URL`, `AGENT_URL`, `MAILPIT_URL`, token, healthcheck on `/api/health`, no `depends_on`) and `diagnostics-agent` (build `apps/diagnostics-agent/Dockerfile`, profile, `pid: host`, `cgroup: host`, `user: root`, `cap_drop: [ALL]`, `cap_add: [SYS_PTRACE]` only if spike A1 shows it is required, `read_only: true`, `security_opt: [no-new-privileges:true]`, tmpfs `/tmp`, volumes `/sys:/sys:ro`, `/var/run/docker.sock:/var/run/docker.sock:ro`, `./infra/ai/llama-models.ini:/cfg/llama-models.ini:ro`, no ports, healthcheck). `api` and `web` get the `DIAGNOSTICS_*` env with default `false`. Pinned base images, no new named volumes.
- **Privilege honesty (ADR 0006 and risks).** `pid: host` exposes every host process' command line and fdinfo to the container; `cgroup: host` and `/sys:ro` expose host hardware and cgroup state; a read-only mount of the Docker socket does not restrict the Docker API (the `:ro` only protects the socket file), so a compromised agent could drive Docker. Mitigations: profile off by default, no published port, stdlib-only code with a GET allowlist, `read_only`, `cap_drop ALL`, `no-new-privileges`, token on its endpoint, demo machine only. Alternative recorded in the ADR: a docker-socket-proxy with `CONTAINERS=1`, or reading cgroups and `/proc` without the socket (loses names and health).
- **Launch and init.** `launch-demo.sh` as Decision 15, plus the printed layout. `init.sh` adds only non-blocking checks (never starts the profile): `docker compose --profile diagnostics config -q` succeeds, and with the default env `GET /diagnostics/topology` without a token is 404 (module off).

Rehearse with `?source=replay`; the video screenshots (PRD section 8) capture both. The PRD section 8 text is updated with this layout.
- **Failure modes.** Header status chip `LIVE | RECONNECTING | API DISABLED | NO AGENT | REPLAY`. Stream drop: native `EventSource` reconnect plus server backoff and `Last-Event-ID`; a `bootId` change clears state and writes a marker row; a sequence gap writes "events missed". `DIAGNOSTICS_ENABLED=false` on the API: banner "API stream disabled: start with DIAGNOSTICS_ENABLED=true". Agent down: widgets `no data`, edges and log continue. No amdgpu: VRAM and GPU `n/a`, CPU and RAM still shown. Wrong token: banner "token mismatch". Event queue in the UI is capped (5000 rows, oldest dropped from the DOM, never from the buffer).
- **Test layering.** Unit and HTTP tests in `pnpm -r test` need no GPU, Docker or network: redaction, ring buffer, event model, token guard on the kitchen test app, the demo-path catalog test with fake adapters and gated fakes, agent parsers on fixtures, UI reducers.
